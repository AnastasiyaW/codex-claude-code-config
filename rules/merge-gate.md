# Гейт слияния: в master/main только через safe_merge

## Правило

PR попадает в основную ветку (master/main или ветка по умолчанию удалённого репозитория)
только если:

1. все проверки на **точном head-коммите** PR зелёные (SUCCESS, SKIPPED или NEUTRAL),
   ни одной в ожидании (включая незавершённые наборы проверок GitHub Actions, у которых
   задачи ещё не созданы), и хотя бы одна именно SUCCESS;
2. head уже **содержит текущую вершину основной ветки**, то есть CI проверил именно то дерево,
   которое окажется в основной ветке (семантика merge queue).

Единственный путь слияния для агента:

```bash
python ~/.claude/claude-code-config/scripts/safe_merge.py <owner/repo> <pr>
```

Прямой `git push` в основную ветку запрещён в любом репозитории: своя работа уходит в ветку
фичи и PR. Чтение (`gh api` GET, `gh pr view`, `git pull`) не ограничено.

Коды: `0` слито (или уже было слито), `1` отказ или ожидание (причина напечатана),
`2` не проверено. Код 1 с `updated-waiting-ci` значит: ветку PR обновили merge-коммитом
(не rebase), нужно дождаться CI на новом head и запустить ещё раз. Каждый запуск печатает
строки `SCANNED:` и `RECEIPT:` и дописывает квитанцию в `~/.claude/logs/safe-merge.jsonl`.

## Репозиторий без CI и просьба владелицы влить

Когда владелица в чате просит влить PR, а в репозитории нет CI (`no-checks`), агент вливает сам:
`safe_merge.py <owner/repo> <pr> --owner-approved-no-checks`. Флаг снимает только отказ
`no-checks`; красные или ждущие проверки, черновик, чужая база и head без вершины основной ветки
отказывают по-прежнему. `merge-gate-guard` пропускает флаг, только если последнее сообщение
владелицы в журнале сессии просит влить («влей», «вливай», «мерж», «merge»), без отрицания и не
вопросом. Перед слиянием агент сам прогоняет локальные проверки репозитория на head PR.

## Почему в обвязке, а не на GitHub

На приватном репозитории бесплатного плана rulesets и merge queue недоступны
(`gh api repos/<owner>/<repo>/rulesets` отвечает 403 «Upgrade to GitHub Pro»). Поэтому гейт
держит обвязка агента, и он одинаков для всех репозиториев, где работают агенты.

## Политика репозитория: `.github/merge-gate.json`

Читается из **основной ветки**, не из PR: PR не может сам себе расширить список исключений.

```json
{
  "allow_unavailable": [
    {"name": "<имя проверки>", "reason": "<почему не может пройти>", "expires": "YYYY-MM-DD"}
  ],
  "required": ["<имя проверки>"],
  "integration_branches": ["<ветка>"],
  "allow_no_checks": "<почему в репозитории нет CI>"
}
```

- `allow_unavailable` — проверки, известно заблокированные снаружи (биллинг, раннер). Срок
  обязателен и не дальше 90 дней; просроченная запись останавливает **все** слияния, пока её
  не продлят с новой причиной или не починят проверку.
- `required` — проверки, которые обязаны появиться на head.
- Без CI и без `allow_no_checks` слияние отказывается: «ничего не проверено» не равно «зелено».
- Неизвестный ключ — ошибка (`2`): опечатка не должна молча выключить правило.

Первый `merge-gate.json` для репозитория без CI (или с проверкой, которую он и должен
внести в исключения) этим путём не вливается: политика читается из основной ветки, а там
её ещё нет. Такой первый PR вливает владелец или он ждёт починки проверки.

## Механически

- `hooks/merge-gate-guard.py` (PreToolUse `Bash|PowerShell`, оба харнесса) блокирует
  `gh pr merge`, вызовы `gh api`/HTTP, которые сливают или двигают ветку, и `git push`
  в защищённую ветку в любом написании (кавычки, пути, обёртки, ssh, `bash -c`, `python -c`,
  алиасы gh и git, подстановки). Обхода нет: экстренное слияние делает владелица сама.
- Почему `safe_merge.py` проходит без токена: хук видит только команды агента, а свой
  `gh pr merge` скрипт запускает дочерним процессом, мимо хука.
- Остаточный риск: скрипт-файл, написанный заранее и запущенный потом; GraphQL-запрос из
  файла; свой HTTP-клиент; фоновые процессы. Хук ловит случайность и привычную однострочку,
  не намеренный обход. Лок слияний — на машину; гонку между машинами ловит проверка
  родителей merge-коммита после слияния (код 2, если слитое дерево не равно проверенному).

Тесты: `hooks/tests/test_merge_gate_guard.py`, `scripts/tests/test_safe_merge.py`
(через поддельный `gh`), `--self-test` у обоих.

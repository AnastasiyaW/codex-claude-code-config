# Живое дерево только принимает — работаем каждый в своём worktree

## Принцип (2026-08-04, прямая директива пользователя)

> «Перестать делить дерево. У git для этого есть готовый механизм: каждому агенту своё
> рабочее дерево, коммиты в общую ветку, а живое дерево только принимает готовое и
> никогда не редактируется руками. Тогда затереть чужой файл физически нельзя — у тебя
> его просто нет. Это настоящая починка.»

**Лок говорит «пожалуйста, не надо». Отдельный чекаут означает, что затирать нечего.**

## Почему этого правила не было и почему оно нужно

[Принцип 18](../principles/18-multi-session-coordination.md) видел этот механизм — он у
него в таблице чужих решений («parallel-cc: git worktrees + sandboxes — full isolation,
no shared state exists»; «Kmux: per-agent worktrees») — и **не взял его**. Вместо этого
он принял общее дерево как условие задачи и построил координацию внутри: append-only
файлы для одного класса состояния, advisory-локи для другого. Формулировка «два сеанса
редактируют один конфиг, один затирает другого» стоит у него в списке *проблем, вокруг
которых надо координироваться*, а не в списке того, что можно убрать.

Разница не теоретическая. За одну смену 2026-08-04, в одном хабе, трижды:

- ветка ушла из-под правки, потому что параллельная сессия коммитнула в неё;
- `git add <каталог>` застейджил чужие незавершённые изменения;
- тот же add **упал целиком** на длинном пути из поддерева третьей сессии, из-за чего
  handoff молча не закоммитился вообще.

Ни одно из трёх не ловится локом: лок защищает файл, который ты назвал, а здесь беда
пришла через операции над *деревом*.

## Правило

1. **Правки — в своём worktree.** `git worktree add .claude/worktrees/<name> -b <branch>`.
2. **Главный чекаут только принимает** — `pull` / `merge` / `checkout`. Руками в нём
   отслеживаемые файлы не редактируются.
3. **Исключение — append-only артефакты.** Handoffs, chronicles, briefs, research,
   журналы: один файл на сессию, никто чужой его не трогает. Здесь изоляция ничего не
   покупает, а рабочий процесс ломает. Это Type 1 из принципа 18, и там он прав.
4. **Новый (неотслеживаемый) файл создавать можно** — чужого в нём нет по определению.

## Механически

[`hooks/live-tree-guard.py`](../hooks/live-tree-guard.py), PreToolUse на
`Write|Edit|MultiEdit`, подключён на **обоих** харнессах. Блокирует правку
**отслеживаемого** файла в **главном** чекауте репозитория, который объявил себя живым.

- **Opt-in по маркеру `.claude/live-tree`** в корне репозитория. Блокировать все репозитории
  на машине — это non-monotonic вред, который эта же кодовая база уже задокументировала
  (`quality-code.md`): гард, который мешает несвязанной работе, отключают, а не настраивают.
- Linked worktree определяется детерминированно: `git-dir` ≠ `git-common-dir`.
- Обход: `CLAUDE_ALLOW_LIVE_TREE_EDIT=1` или удалить маркер.
- `--self-test` поднимает настоящий временный репозиторий с настоящим worktree.

Всего 1969. То есть 44 % работы уже шло по правильной схеме, а 21 % переезжает. Верх
списка блокируемых — `PROBLEMS.md` (92), ровно тот файл, за который в этот день
столкнулись две сессии.

## Анти-паттерны

- ❌ Считать лок заменой изоляции. Лок — это обещание; отдельное дерево — это факт.
- ❌ Включать правило разом на всех репозиториях. Опт-ин по маркеру, иначе его снесут.
- ❌ Тащить под правило append-only артефакты: они конфликт-фри по построению, и запрет
  сломает handoff-процесс ради нулевой выгоды.
- ❌ `git add <каталог>` в общем дереве — стейджит чужое и падает на чужих длинных путях.
  Явные пути (это же требование в `git-source-of-truth.md`).
